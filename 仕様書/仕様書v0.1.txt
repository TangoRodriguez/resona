# RESONA 仕様書 v0.1

## 声に触れる。音がかたちになる。人と共鳴する。

---

## 0. RESONAの一文定義

**RESONAは、声・鼻歌・タッチ・周囲の音をリアルタイムに解析し、楽器音・ループ・ビジュアル物性へ変換するWebインタラクティブ音楽アプリである。**

1人では、ヒーリング・作曲メモ・即興演奏アプリとして使える。
複数人では、各ユーザーの音が同期・変換・融合し、ひとつの共有音楽空間になる。

---

# 1. プロダクトの核

## 1.1 何を作るのか

RESONAは、普通のDTMアプリではない。

ピアノロールを打ち込むアプリでもない。
波形編集ソフトでもない。
単なるビジュアライザーでもない。

目指すのは、

> **声やタッチが、音楽と視覚的な“物性”に変わる体験**

である。

ユーザーが声を出す。
その音程が抽出される。
音階に補正される。
ガラス、膜、水、結晶、粒子のような音色に変換される。
同時に、画面上のオブジェクトもその音色に応じた見た目・動き・触り心地を持つ。

つまり、

**音を聴く**
だけではなく、
**音に触る**
**声を見る**
**メロディを形として掴む**
**人と音で混ざる**

ことができるアプリにする。

---

# 2. 基本コンセプト

## 2.1 メインコンセプト

## **Sound becomes matter.**

## **音が、物質になる。**

ガラスの音は、ガラスのUIになる。
水のような音は、水面のUIになる。
声は、膜や光の線になる。
低音は、重力になる。
リズムは、脈動する円になる。
複数人の同期は、別々の物質が融合する現象として表現される。

---

## 2.2 サブコンセプト

### 1. Voice to Instrument

声をそのまま再生するのではなく、**楽器へ変換**する。

### 2. Melody Trace

鼻歌や歌声から、**リアルタイムでメロディを抽出**する。

### 3. Visual Matter

音色や音の特徴を、**触れるビジュアル物性**として表示する。

### 4. Healing Loop

録音した音や声を、**癒し系のループ音楽**に変換する。

### 5. Sync Room

複数人の入力を、**同じBPM・キー・空間に同期**する。

### 6. Simple Surface

機能は深いが、UIはあくまで**シンプルで直感的**にする。

---

# 3. RESONAの思想

## 3.1 ユーザーに音楽理論を要求しない

ユーザーはスケール、コード、BPM、量子化、フィルター、リバーブを知らなくていい。

アプリ側が裏で処理する。

ユーザーがやることは、

* 声を出す
* 触る
* 録る
* 重ねる
* つながる

だけ。

---

## 3.2 失敗しても綺麗に鳴る

普通の音楽アプリは、間違えると変な音になる。
RESONAは逆。

ズレた声も、震えた声も、曖昧な鼻歌も、息だけの入力も、全部素材として扱う。

ただしそのまま鳴らさず、

* スケール補正
* 音程スムージング
* 自動ハーモニー
* 音量制御
* リバーブ
* グラニュラー加工
* 音色変換

を通して、美しく聴こえるようにする。

---

## 3.3 直接の声ではなく、声の気配を共有する

複数人モードでは、相手の声がそのまま聞こえる必要はない。

むしろ、直接声が聞こえると通話アプリっぽくなる。

RESONAでは、

> **相手の声そのものではなく、相手の音楽的特徴が聞こえる**

ようにする。

例えば、

* 相手の音程
* 声の揺れ
* 息の量
* 入力の強さ
* リズム
* メロディの輪郭

だけが抽出され、楽器音やビジュアルとして現れる。

これはかなり重要。

RESONAは通話アプリではなく、**共鳴アプリ**。

# 4. ターゲット体験

## 4.1 1人で使う場合

### 用途

* 寝る前に癒し音を作る
* 鼻歌からメロディを保存する
* 声を楽器にして遊ぶ
* 作曲の種を作る
* 集中用BGMを即興生成する
* 自分の声を直接聞かずに音楽化する
* 気分を音として記録する

### 体験例

ユーザーがアプリを開く。
中央に透明なガラス球のようなオブジェクトがある。

ユーザーが小さくハミングする。
アプリが音程を拾い、ベルのような音で返す。
声の軌跡が光の線として表示される。

RECを押す。
直前のメロディが保存され、円形のループとして回り始める。

もう一度声を入れる。
今度はパッド音になって、最初のメロディに重なる。

ユーザーは音楽理論を知らなくても、数十秒で美しいループを作れる。

---

## 4.2 2人で使う場合

### 用途

* 友達と音で遊ぶ
* 遠隔でゆるく音楽を作る
* 声を直接聞かせず、気配だけ共有する
* カップルや友人同士で癒し空間を作る
* 一緒に即興演奏する

### 体験例

ユーザーAが作ったループを持ったまま、SYNCを押す。
URLを友達に送る。

友達Bが入室する。
Bの音は、Aの画面上に別の光体として表示される。

Bが声を入れる。
その声は直接聞こえず、柔らかいパッドとしてAのループに混ざる。

Aのメロディがルート音、Bのメロディが3度や5度に補正される。
2人の音が自然に和音になる。

---

## 4.3 大人数で使う場合

### 用途

* 展示
* 学園祭
* ライブ前演出
* メディアアート
* ワークショップ
* 空間演出
* インタラクティブ音楽体験

### 体験例

会場にQRコードがある。
参加者がスマホから入る。

各自が声を入れる、画面を触る、スマホを傾ける。
それぞれの入力は、会場PCの大画面に反映される。

画面上には、たくさんの音のオブジェクトが浮かぶ。
同期率が上がると、それらが一つの構造体になっていく。

最終的に、会場にいた人たちだけの音楽が生成され、録音される。

# 6. UI基本方針

## 6.1 UIの原則

RESONAのUIは、複雑にしない。

### 原則

1. 画面中央に大きなインタラクティブオブジェクトを置く
2. ボタンは最大3つまで
3. 設定は隠す
4. 音色選択は「物性選択」として見せる
5. 録音やループは視覚的に理解できるようにする
6. 初見でも10秒以内に触れるようにする
7. DTM用語を前面に出さない
8. 触って気持ちいいことを最優先する

---

# 7. 操作仕様

## 7.1 タップ

### 動作

画面上の音オブジェクトをタップすると、短い音が鳴る。

### 音への影響

* タップ位置Y：音程
* タップ位置X：パンまたは音色
* タップ強度相当：音量
* 連続タップ：リズム生成

### ビジュアルへの影響

* ガラスなら光の点
* 水なら波紋
* 結晶なら小さな枝
* 粒子なら弾ける
* 膜なら小さく震える

---

## 7.2 スワイプ

### 動作

指でなぞると、メロディまたは音色変化が起きる。

### 音への影響

* 上方向：音程上昇
* 下方向：音程下降
* 右方向：明るくなる
* 左方向：暗くなる
* 速いスワイプ：粒子音
* 遅いスワイプ：滑らかなグライド

### ビジュアルへの影響

スワイプの軌跡が光の線として残る。
その線は短時間だけ鳴り続ける。

---

## 7.3 長押し

### 動作

現在の音を固定する。

### 機能名

**Hold** または **Freeze**

### 音への影響

* 今鳴っている音を持続音にする
* ループ候補として保存する
* リバーブを伸ばす
* ドローン化する

### ビジュアルへの影響

* 音オブジェクトが固まる
* ガラスなら透明な結晶になる
* 水なら波紋が円環になる
* 膜なら張力が固定される

---

## 7.4 ピンチ

### 動作

二本指で広げる/縮める。

### 音への影響

* 広げる：リバーブ増加、空間拡大
* 縮める：音が近くなる、ドライになる
* 回転：フィルターやモジュレーション変化

### ビジュアルへの影響

* オブジェクトが広がる
* 奥行きが変わる
* 光の屈折が変化する

---

## 7.5 声入力

### 動作

ユーザーが声や鼻歌を入れる。

### 解析する特徴

* 音量
* ピッチ
* 音程の安定度
* メロディ輪郭
* 息っぽさ
* 声の明るさ
* アタック
* リズム

### 音への変換

* 楽器音へ変換
* スケール補正
* メロディ化
* ハーモニー生成
* パッド化
* ベース生成
* グラニュラー化

### ビジュアルへの変換

* メロディ線
* 光の帯
* 膜の揺れ
* 結晶成長
* 水面の変形
* ガラスの屈折

# 9. 音声解析仕様

## 9.1 入力

マイクからリアルタイム音声を取得する。

### 取得対象

* 声
* 鼻歌
* ハミング
* 口笛
* 息
* 周囲の音
* 楽器音

---

## 9.2 解析パラメータ

| パラメータ       | 用途           |
| ----------- | ------------ |
| Volume      | 音量、ビジュアルの大きさ |
| Pitch       | 音程、メロディ      |
| Confidence  | ピッチの確からしさ    |
| Brightness  | 音色の明るさ       |
| Breathiness | 息っぽさ、ノイズ量    |
| Attack      | リズム、粒子発生     |
| Stability   | 音の安定度        |
| Duration    | 音符の長さ        |
| Onset       | 音の開始位置       |
| Silence     | 無音判定         |

---

## 9.3 ピッチ検出

### 目的

声や鼻歌の基本周波数を推定する。

### 必要仕様

* 低遅延
* 多少ノイズがあっても安定
* 無音時に誤検出しにくい
* 音程が揺れても滑らかに追従

### 出力

```text
pitchHz: 261.63
note: C4
confidence: 0.87
volume: 0.52
```

---

## 9.4 メロディ抽出

### 処理

```text
マイク入力
↓
音量しきい値判定
↓
ピッチ検出
↓
短時間の揺れを平滑化
↓
音符境界を推定
↓
音程を近い音名に丸める
↓
スケール補正
↓
メロディ列として保存
```

### 出力例

```text
[
  { note: "C4", start: 0.0, duration: 0.5, velocity: 0.7 },
  { note: "Eb4", start: 0.5, duration: 0.5, velocity: 0.6 },
  { note: "G4", start: 1.0, duration: 1.0, velocity: 0.8 }
]
```

# 10. 音楽変換仕様

## 10.1 スケール補正

ユーザーの声をそのまま鳴らすと音痴っぽくなる場合がある。
そのため、選択中のキー・スケールに近い音へ補正する。

### デフォルトスケール

| モード      | スケール                       |
| -------- | -------------------------- |
| Heal     | Minor pentatonic           |
| Glass    | Major pentatonic           |
| Liquid   | Dorian                     |
| Fabric   | Minor / sus系               |
| Gravity  | Root + fifth中心             |
| Particle | Pentatonic + random octave |

---

## 10.2 補正の強さ

### Gentle

声の揺れを残す。
自然。

### Align

スケールにしっかり寄せる。
綺麗に聞こえる。

### Lock

完全に音階へ固定。
展示や複数人向き。

UI上にはこの言葉を出さず、内部設定として持つ。

---

## 10.3 自動ハーモニー

入力メロディに対して、自動で和音を生成する。

### 方式

* 3度上
* 5度下
* オクターブ下
* ドローン
* sus2
* add9
* maj7
* minor7

ヒーリング寄りなので、派手なドミナント進行より、浮遊感のある和声を優先する。

---

## 10.4 ループ化

### 目的

録音した声やメロディを、気持ちよく繰り返せるようにする。

### 処理

* 開始位置調整
* 終了位置調整
* BPMに合わせる
* フェードイン/アウト
* 音量正規化
* 必要に応じてリバーブ付与
* ループ境界のクリック除去

---

# 11. 録音仕様

## 11.1 Capture

RESONAでは録音を **Capture** と呼ぶ。

録音というより、
**その瞬間の音の形を捕まえる**
という意味。

---

## 11.2 Capture操作

| 操作     | 動作       |
| ------ | -------- |
| タップ    | 録音開始/停止  |
| 長押し    | 直前10秒を保存 |
| 上スワイプ  | ループ化     |
| 下スワイプ  | 削除       |
| ダブルタップ | Freeze   |

---

## 11.3 Back Capture

### 概要

録音ボタンを押す前の音も保存する機能。

### なぜ必要か

メロディのアイデアは、録音ボタンを押す前に出ることが多い。

そのため、常に直前10秒程度の音声特徴を内部保存しておく。

### 保存対象

* Raw audio
* Pitch data
* Melody data
* Visual motion
* Processed sound

初期版ではRaw audioは保存せず、メロディデータだけ保存でも良い。

---

## 11.4 Orbit

録音されたループを **Orbit** と呼ぶ。

### 意味

録音した音が、画面上を回る衛星のように存在し続ける。

### 表示

* 小さな円
* 光のリング
* 結晶
* 波紋
* 軌道

### できる操作

* タップでミュート
* 長押しで削除
* ドラッグで音量変更
* 上へ移動で高音化
* 下へ移動で低音化
* 中央に近づけると他のループと融合

---

# 12. 複数人同期仕様

## 12.1 Merge

RESONAでは同期を **Merge** と呼ぶ。

単にオンライン接続するのではなく、
**音と視覚物性が混ざる**
という意味を持たせる。

---

## 12.2 ルーム

### 作成

ユーザーがMergeを押すとルームが作られる。

### 参加方法

* URL共有
* QRコード
* ルームコード

### 表示

```text
3 people resonating
```

または日本語なら、

```text
3人が共鳴中
```

---

## 12.3 同期対象

複数人時に同期するもの。

| 対象           | 内容       |
| ------------ | -------- |
| BPM          | 全員の拍     |
| Key          | 全員の基準キー  |
| Scale        | 使える音階    |
| Section      | 曲の展開     |
| Visual tempo | ビジュアルの呼吸 |
| Loop start   | ループ開始位置  |
| Density      | 音の密度     |
| Mood         | 音色方向     |

---

## 12.4 同期しないもの

全部を同期すると個性が消える。

以下は個人差として残す。

| 対象         | 理由     |
| ---------- | ------ |
| 声の揺れ       | 個性     |
| 入力タイミングの微差 | 人間らしさ  |
| 音色の細部      | 個人の気配  |
| ビジュアルの個体差  | 自分の存在感 |
| ループ内容      | 個人の記憶  |

---

## 12.5 複数人の音の整理

複数人が同時に入力すると音が濁る。
そのため、システムが自動で役割分担する。

### 役割

| Role    | 音の役割  |
| ------- | ----- |
| Root    | 基準音   |
| Harmony | ハモリ   |
| Pad     | 背景    |
| Bell    | 高音    |
| Pulse   | リズム   |
| Gravity | 低音    |
| Texture | 粒子・空気 |

ユーザーには見せても見せなくてもいい。
見せるなら、

```text
You are: Glass Bell
```

くらいが良い。

---

# 13. 同期率

## 13.1 Sync Score

複数人の同期度を数値化する。

### 入力

* タップが拍に合っているか
* 声の音程がスケール内にあるか
* 入力の周期が近いか
* 音量変化が似ているか
* ループ開始が揃っているか
* 無音と発音のタイミングが近いか

### 出力

```text
syncScore: 0.72
```

---

## 13.2 Sync Scoreによる変化

| Sync Score | 音         | ビジュアル    |
| ---------- | --------- | -------- |
| 0.0〜0.3    | バラバラ、粒が多い | 個別に動く    |
| 0.3〜0.6    | ゆるくまとまる   | 線がつながる   |
| 0.6〜0.8    | 和音が安定     | 形が融合する   |
| 0.8〜1.0    | 大きな展開     | 全体が発光・統合 |

# 17. 現時点の完成イメージ

RESONAを開く。
黒に近い背景の中央に、透明なガラスのような球がある。

タップすると、澄んだ音が鳴る。
光の波紋が走る。

鼻歌を歌うと、声が直接再生されるのではなく、透明なベルと柔らかいパッドになる。
歌ったメロディは、光の線として画面に残る。

Captureを押すと、そのメロディがOrbitとして回り始める。
もう一度声を入れると、アプリが自動でハモリを作る。

Mergeを押すと、友達が入ってくる。
友達の声は、別のガラス片として現れる。
2人のメロディが自然に同じキーへ吸い寄せられ、和音になる。

人数が増えるほど、画面上の音の物体は複雑になる。
しかしUIはシンプルなまま。

ユーザーが見ているのは、設定画面ではない。
**音に触れる画面**。
